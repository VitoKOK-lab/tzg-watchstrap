## 信件內容與可靠性

- 包含諮詢編號、三類服務之一、稱呼、聯絡方式、預算、款式型號、材質、顏色、網站價格、手錶尺寸與補充需求。
- 既有設計的價格由伺服器依商品資料重算；四色同價，均不含 Apple Watch 主機。單品錶殼方案也註明不含錶帶。
- 客人填 Email 時設定 Reply-To，可直接回覆客人；選電話時不設定 Reply-To，請依信件中的電話聯繫。
- 使用者文字經 HTML 跳脫處理，API 檢查來源、內容長度、必填資料、款式組合及蜜罐欄位。
- 原始資料不寫入 GitHub、應用程式日誌或新的網站資料庫；寄信服務與收件信箱會處理並保留信件。
- 網頁只有在 Gmail SMTP 接受兩個收件人及郵件後才顯示送出成功。若只有部分收件人被接受也回傳失敗，請檢查送信結果後跟進。失敗時保留輸入，供重試或改用 LINE。
- Gmail 重試沿用相同諮詢編號及 Message-ID，便於人工辨識；SMTP 不保證去重，連線中斷或部分投遞後再重試可能收到重複信件，請依諮詢編號合併處理。Resend 替代模式使用 24 小時有效的 idempotency key。
- 蜜罐和來源檢查不能取代完整防濫用；如遇機器人大量填表，需在 Vercel 加上流量限制或驗證碼。Gmail 可能因寄信配額、帳戶安全檢查或雲端伺服器連線而拒絕寄信；正式上線前必須實際投遞驗證。

## 建置與驗證

- 正式網站：https://tzg-watchstrap.vercel.app/
- Vercel：`npm run build:vercel`（Next.js，產出 `.next`）。倉庫根目錄即專案根目錄。
- 本機：`npm run dev`；原 Sites/Vinext 建置：`npm run build`。
- `node scripts/verify-vercel.mjs`：未設定寄信時安全停用、後台鎖定、偽造登入標頭不可讀取或更新資料。測試子程序會清空寄信變數，不影響正式環境。
- `node scripts/verify-inquiry-email.mjs`：對實際 Next.js build 使用本機 Resend 測試替身，驗證雙收件人、伺服器價格、HTML 跳脫、重試內容穩定、三類服務、輸入拒絕、寄信服務錯誤與密鑰不出現在首頁。此測試不會寄出真實 Email。

- `node scripts/verify-gmail-inquiry.mjs`：對正式 Next.js build 使用本機 SMTP 測試替身，驗證固定 Gmail 寄件人、TLS、雙收件人、Reply-To、價格、防止密鑰進入首頁，以及部分／全部 SMTP 失敗時不顯示成功。不會寄出真實 Email。

官方文件：https://support.google.com/accounts/answer/185833?hl=zh-Hant 、 https://nodemailer.com/smtp 、 https://resend.com/docs/dashboard/emails/idempotency-keys
