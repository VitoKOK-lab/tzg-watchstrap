# 諮詢表單與 Email 收件

## 已選定的流程

客人免登入填寫網站表單，Vercel 伺服器透過 Resend 寄送完整諮詢至兩個固定收件信箱：

- tzgrotw@gmail.com
- luxkey.tw@gmail.com

網站不建立新的線上諮詢名單，不需要 Supabase 或管理者登入。請在 Gmail 查看、回覆或用標籤追蹤。舊 D1 後台程式保留供既有資料使用，Vercel 上仍鎖定；公開頁面已移除管理登入連結。

## 正式啟用前仍需完成

1. 在 Resend 加入品牌寄件網域，依其提供的 DNS 記錄驗證，並確認可寄信。
2. 使用該網域的寄件地址，建立僅具寄信權限的專案 API key。
3. 在 Vercel 的 tzg-watchstrap 專案設定伺服器環境變數：
   - `RESEND_API_KEY`：寄信 API key。
   - `INQUIRY_FROM_EMAIL`：已驗證網域上的單一寄件地址（不含顯示名稱）。
4. 重新部署。正式環境設定完成前，網站保持 LINE 聯繫模式，API 回傳 503，不會假裝收件成功。
5. 從正式網站填寫一筆明確標示為測試的諮詢，確認兩個信箱都實際收到，並檢查 Resend 的投遞結果。API 接受不等於已進收件匣。

目前程式已完成；截至 2026-09-20 本次檢查，Resend 帳號尚無驗證網域，尚未配置正式密鑰，也尚未完成真實投遞驗證。

密鑰僅存在 Vercel 伺服器環境，不得使用 `NEXT_PUBLIC_`，也不得提交 GitHub。收件人由伺服器固定指定，客人不能透過表單變更收件人。

## 信件內容與可靠性

- 包含諮詢編號、三類服務之一、稱呼、聯絡方式、預算、款式型號、材質、顏色、網站價格、手錶尺寸與補充需求。
- 既有設計的價格由伺服器依商品資料重算；四色同價，均不含 Apple Watch 主機。單品錶殼方案也註明不含錶帶。
- 客人填 Email 時設定 Reply-To，可直接回覆客人；選電話時不設定 Reply-To，請依信件中的電話聯繫。
- 使用者文字經 HTML 跳脫處理，API 檢查來源、內容長度、必填資料、款式組合及蜜罐欄位。
- 原始資料不寫入 GitHub、應用程式日誌或新的網站資料庫；寄信服務與收件信箱會處理並保留信件。
- 網頁只有在 Resend 接受請求並回傳訊息 ID 後才顯示送出成功。失敗時保留輸入，供重試或改用 LINE。
- 同一次內容重試使用穩定的 idempotency key。Resend 去重有效期為 24 小時；重新整理、修改內容或超過有效期可能產生新信件，不能保證永久去重。
- 蜜罐和來源檢查不能取代完整防濫用；如遇機器人大量填表，需在 Vercel 加上流量限制或驗證碼。寄信配額及退信應由 Resend Dashboard 監看。

## 建置與驗證

- 正式網站：https://tzg-watchstrap.vercel.app/
- Vercel：`npm run build:vercel`（Next.js，產出 `.next`）。倉庫根目錄即專案根目錄。
- 本機：`npm run dev`；原 Sites/Vinext 建置：`npm run build`。
- `node scripts/verify-vercel.mjs`：未設定寄信時安全停用、後台鎖定、偽造登入標頭不可讀取或更新資料。請在未設定寄信變數的環境執行。
- `node scripts/verify-inquiry-email.mjs`：對實際 Next.js build 使用本機 Resend 測試替身，驗證雙收件人、伺服器價格、HTML 跳脫、重試內容穩定、三類服務、輸入拒絕、寄信服務錯誤與密鑰不出現在首頁。此測試不會寄出真實 Email。

官方文件：https://resend.com/docs/api-reference/emails/send-email 、 https://resend.com/docs/dashboard/emails/idempotency-keys
